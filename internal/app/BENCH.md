### Chrome-only repaint

The target in `docs/gui-contract.md` is < 8 ms for a chrome-only repaint at 1x. **This target is missed with the real chrome UI**: the `engine paint: chrome` row above is the engine's own cost of repainting the chrome page (every chrome mutation repaints the whole transparent window-sized chrome, because dropdowns, toasts and the find bar can overlap the viewport hole, so the repaint cannot be limited to the tab strip), and the keystroke row is the end-to-end figure (event -> chrome JS -> chrome paint -> compose -> Present). The cost is dominated by the engine's raster of the chrome's display list (gradients, shadows, rounded rects, text) rather than by this package; the placeholder chrome, which is a plain few-element page, repainted in under 4 ms (run with `-placeholder`). A region-limited, display-list-diffing engine paint is the fix and is not done.

With the sidebar open (chrome painted at full window height): keystroke latency p50 105.26 ms, p99 135.82 ms.

## How to compare with Chrome

`bench/gui_vs_chromium.sh` (or the Chromium section above, which this program runs when a Chromium binary is found) launches headless Chromium on the same local fixture pages and records (a) wall time from exec to a finished `--screenshot`, and (b) peak resident and proportional (PSS) memory summed over the whole process tree with 1 and 10 tabs open. Chromium is multi-process, so a single-process RSS is not comparable; PSS summed over the tree is the fair figure.

What the comparison does **not** show: Chromium here is headless and draws no browser UI (tab strip, omnibox, sidebar), while Sweef's number includes painting its entire chrome through its own engine; Chromium renders far more of the web correctly. Do not quote the ratio without those caveats. Use `-skip-chromium` to omit it.
