## Cross-check: proxy bytes vs the browsers' own counters

The proxy sees encrypted bytes on the socket, which includes TLS handshakes, TLS record framing, HTTP/2 framing, request headers and anything the page requested that the browser does not itemise. Chromium's CDP `encodedDataLength` is the response transfer size (headers and body as received, before TLS record overhead). CDP has no request-size counter, so "CDP out" is an estimate: request line plus the header lines CDP reports for each request, uncompressed (HTTP/2 compresses headers, so this over-states), plus POST bodies. Sweef's own counters (`DataStats.WireIn/WireOut`, exact socket totals of the context) are shown when the engine API exists; the engine counts at its dialer, which also sees the CONNECT exchange with the recorder (about 40 bytes in and 90 out per connection), so that exchange is added to the proxy figure for this comparison only.

## Method

**What is measured.** For every site, mode and run: one cold visit, then one warm visit. Each visit is `load` plus a fixed 5 s idle window, then the counters are read. The same 5 s applies to every browser. 3 runs per cell; tables show the median with the minimum and maximum. Run order is rotated per run so no mode is always first or last.

**The independent counter.** Every browser is pointed at its own tiny recording HTTP CONNECT proxy written for this harness (`bench/datasaver/recproxy.go`), which forwards through the sandbox proxy (`HTTPS_PROXY`) and counts, per connection, the bytes it writes in each direction after the CONNECT handshake. For https it only tunnels, so it sees the encrypted bytes: TLS handshake, TLS records, HTTP/2 or HTTP/1.1 framing. That is what a metered connection bills, minus TCP/IP headers. One recorder is created per browser launch, so runs cannot contaminate each other. The recorder has a test that compares its counts to a byte counter on the far side of a real TLS connection.

**Cross-check.** The browsers' own counters are collected separately and compared in the cross-check table: Chromium `Network.loadingFinished.encodedDataLength` (plus redirect responses) and request headers from CDP, and Sweef's `DataStats.WireIn/WireOut` once the engine exposes them. The proxy figures are the ones used in every other table; the browser counters are only a check.

**Chromium.** The binary at `/opt/pw-browsers/chromium`, `--headless=new --no-sandbox`, a fresh `--user-data-dir` for every cold visit and a new process on the same directory for the warm visit. Flags that stop it generating non-page traffic: `--disable-background-networking --disable-sync --disable-component-update --disable-default-apps --disable-domain-reliability --disable-client-side-phishing-detection --safebrowsing-disable-auto-update --disable-breakpad --metrics-recording-only --no-pings` plus feature switches for optimization hints, translate, media router, autofill server and the certificate-transparency updater. The about:blank baseline table shows what remains. CDP is attached with flat sessions and `Target.setAutoAttach` (paused on start) so iframes, workers and service workers are counted too. The `chromium-savedata` mode additionally sets `Save-Data: on` with `Network.setExtraHTTPHeaders`; it does not enable any Chromium data-saving behaviour (the old DataReductionProxy is gone), so it shows what a plain header does. Viewport 1280x720, same as the Sweef engine default.

**Sweef.** The harness drives the engine in-process (`internal/engine`), one child process per cold visit: fresh engine, fresh cache directory, fresh cookie jar and connection pool, a new `BrowserContext`, default engine options (`DefaultOptions()`, user agent included). `ready` is when `NewTabInContext(url)` returns. The idle window pumps the page's event loop with `Tab.Settle`. Modes `standard` and `strict` apply `engine.PolicyFor(level)` with `SetDataPolicy`; they are only run in a build that has that API (`-tags datasaver_engine`). Sweef `off` today is the engine with nothing blocked, which is what `off` means in the spec.

**Request counts.** Chromium: CDP `requestWillBeSent` for http(s) URLs, one per redirect hop, cache hits included. Sweef: the engine's own network log (`Network.request` events plus cache-hit responses). Connections are counted by the proxy for both.

**Pages per 100 MB.** 100,000,000 bytes divided by the mean wire bytes (in plus out) per page over the included sites, computed once per run index and reported as median, min and max over runs. Per-site tables apply the same formula to a single visit.

**Honesty rules applied.** The tool prints a "% saved" figure only if every mode completed the same sites with every run; otherwise the headline section says why it is withheld. Sites are chosen and frozen beforehand and excluded by a fixed mechanical rule. Savings estimates from the engine (`SkippedEstimate`) are never mixed into measured bytes; the benchmark compares only socket bytes.

## Caveats

* **Single network location, single machine, one day.** All numbers come from one cloud sandbox behind one egress path. Another country, ISP, time of day or CDN edge can change what is served and how it is compressed.
* **Pages change daily.** Front pages, ad auctions and A/B tests mean two runs minutes apart differ; that is why every cell has three runs and a min to max range. Treat differences smaller than the range as noise.
* **Not the same page.** Sweef's engine and Chromium do not fetch the same set of resources. The tables above show what each actually requested; if one fetches no images or fonts, its byte count is lower for that reason alone and says nothing about a data saver. Only the Sweef off/standard/strict comparison holds the engine constant.
* **Headless Chromium without extensions.** No ad blocker, no profile history, no Data Saver of its own. The Chromium user agent has "Headless" removed (client hints too) so sites do not serve it a bot page; Sweef sends its default user agent. Sites may treat the two differently, which the exclusion rule only partly catches (a 200 response with a different page is not detected).
* **Consent banners and geo variation.** No consent is clicked for any browser. Pages from EU-region edges may show a consent overlay that blocks or defers trackers; this sandbox's region decides which variant is served.
* **TLS is re-terminated.** The sandbox's egress gateway terminates TLS with its own certificate chain, so handshake bytes are not exactly what the real site would send. Both browsers see the same chain, so the comparison is fair, but absolute bytes are slightly off from a direct connection. Chromium cannot use QUIC through an HTTP proxy, so it ran HTTP/2 or HTTP/1.1, as did Sweef.
* **What is not counted.** TCP/IP headers, DNS lookups (resolved by the upstream proxy), and the CONNECT exchanges between browser, recorder and upstream proxy. TCP/IP headers would add a few percent to every mode alike.
* **Plain http:// is not forwarded** by the recorder (the sandbox proxy only tunnels). All listed pages are https; any plain-http sub-resource a page asked for is refused and noted per run, which can make a page slightly smaller than in the wild.
* **Sweef WebSockets** are dialled by the engine outside its HTTP transport, so they bypass the recorder; a run in which a page opens one is failed rather than under-counted.
* **Sweef proxy routing is a harness hack.** The engine ignores `HTTPS_PROXY` and `ContextOptions.ProxyURL` today; the harness reaches the engine's HTTP transport by reflection to point it at the recorder, and a dial guard makes any bypass fail. This goes away when the engine supports a proxy.
* **Warm-cache definitions differ by necessity.** Chromium's warm visit is a new process on the same profile (disk cache); Sweef's is the same process and context (memory cache of scripts and styles only; documents are never cached).

```sh
# from the repository root, with Chromium at /opt/pw-browsers/chromium and HTTPS_PROXY set if egress needs it
scripts/bench/datasaver.sh                 # builds with the engine API when it exists, runs all modes, writes results + this page

go run ./bench/datasaver -sites bench/datasaver/sites.txt -runs 3
go run -tags datasaver_engine ./bench/datasaver -runs 3   # once engine.DataPolicy exists: adds Sweef standard and strict
go run ./bench/datasaver report -in bench/datasaver/results/<file>.json -md docs/data-saver-bench.md
```
