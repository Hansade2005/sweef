# Packages the release build compiles without inlining (go build -gcflags=<pattern>=-l), one pattern per line.
#
# Inlining copies small functions into their callers and records every copy in the function metadata (.gopclntab),
# so it costs binary size twice. In packages that run once per connection, per message or per user action the speed it
# buys is not measurable and the bytes are. Everything on a per-pixel, per-byte, per-node or per-request path stays
# inlined: the rasteriser, layout, style, the DOM and the HTML parser, the codecs, WebGL, fonts, the JavaScript engine,
# wazero, goleveldb, compress/*, image/*, the tracker filter, the omnibox, history search, the runtime and
# the core standard library (strings, bytes, strconv, sort, sync, io, bufio, ...).
#
# This list is used by scripts/release/build.sh and cmd/sweef/binsize_linux_test.go. A plain `go build ./cmd/sweef`
# does not use it (development builds stay fast and debuggable); the release is what the size budget is about.
# The measured effect and the benchmarks behind each entry: docs/development.md, "Binary size budget". Add a package
# only with a benchmark that shows no change, and say so in the CHANGELOG.
